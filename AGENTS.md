# Project Working Rules

## Everyday updates

- Update existing documents directly when the user adds information, fills in measurements, corrects wording, or progresses the current design.
- Do not create v1, v2, v3 files, duplicate snapshots, or version headings for routine additions.
- Keep the language natural, clear, and easy for the user to modify.
- Describe the project objectives directly. Do not attribute the scope to a CV or include copied CV descriptions.
- Distinguish planned work from completed work. Do not invent calculations, dimensions, fabrication records, or test results.

## Major new ideas and designs

- Preserve the existing project when the user moves to a substantially different idea or design, especially after completing the current project.
- At that point, use a new heading or a separate v2, v3, etc. design folder or file, as appropriate.
- Keep the previous design, reasoning, results, and CAD dependencies accessible.
- Date the major change, explain what changed and why, and identify the active design.
- Earlier work may be marked superseded, but do not delete it unless the user requests that.

## Project scope

Develop a stair-climbing payload trolley using a three-wheel tri-star cluster mechanism. Cover chassis CAD, mechanism geometry, torque and pull-force analysis, load distribution, centre-of-gravity alignment, fabrication, structural checks, and dynamic payload testing on measured stairs.

The requirements belong in mechanical work, not the problems folder. Record ordinary progress in the existing progress log without creating new design versions.
